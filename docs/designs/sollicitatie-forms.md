## Problem Statement

Candidates who find vacatures on lightpersoneelsdiensten.nl have no way to apply through the website. The only mechanism is a mailto: link that opens their email client. Many candidates (mobile, logistics workers) abandon at that point. Meanwhile, candidates who find vacatures through job boards (Indeed, Nationale Vacaturebank via Jobit/Multiposter) can apply through the board's built-in system. The website is the one channel with no structured apply flow.

Additionally, candidates who don't see a matching vacature have no "open sollicitatie" path on the website.

## Demand Evidence

- Applications already flow through Indeed Apply and board mechanisms. Sandra processes them via email/Jobit dashboard. The workflow exists; the website is just missing from it.
- The website has vacature detail pages with traffic but a mailto: link as the only CTA.
- The existing /api/sollicitatie endpoint already handles SMTP email for a generic contact form.

## Status Quo

- Job board candidates: apply through Indeed Apply, Nationale Vacaturebank, etc. Applications arrive in Sandra's inbox. Works fine.
- Website visitors: see a vacature, click "Solliciteer", their email client opens with a pre-filled subject. Most mobile users bounce here. No structured data captured.
- Open sollicitatie: a mailto: link on the empty vacatures page. No form.

## Target User & Narrowest Wedge

**Primary**: A candidate on their phone who found a vacature on the Light website (via Google, social, or a shared link). They need to submit their contact info in under 60 seconds without a CV, without leaving the page.

**Narrowest wedge**: Two forms on the website. Both email Sandra. No ATS, no database, no marketing tool changes.

## Constraints

- Website only (Astro). No marketing tool changes needed.
- Email is the system of record. Sandra already checks one inbox for all applications.
- Target candidates: logistics/production/cleaning workers, often on mobile, often don't have CVs.
- Dutch only for v1.

## Premises

1. Two forms: per-vacature (inline on /vacatures/[slug]) and open sollicitatie (standalone at /solliciteren). Both send email to Sandra's inbox.
2. Extend existing /api/sollicitatie endpoint. It already does SMTP.
3. sollicitatie_url in XML feed stays EMPTY. Don't redirect board candidates away from Indeed Apply (5x more completions). The website form is only for direct website visitors.
4. (Revised) Form fields: naam, telefoon, email, beschikbaarheid (dropdown), eigen vervoer (ja/nee), bericht (optioneel), CV upload (optioneel, max 5MB, pdf/jpg/png). Seven fields, two optional.
5. Dutch only. Polish candidates call directly.

## Cross-Model Perspective

Independent Claude subagent reviewed the approach:

- **Steelman**: Closing the one conversion gap that matters most for a staffing agency website, routing to email so Sandra's workflow doesn't change.
- **Key insight**: keeping sollicitatie_url empty shows discipline. "The website form is not a replacement for the board apply flow, it's a net-new channel for a different segment."
- **Challenged premise**: no CV upload was wrong. An optional file field costs 30 minutes and captures signal when someone has something to share. **Accepted**.
- **Good additions**: reply-to header on email (Sandra hits Reply directly), structured email body, /solliciteren linked from site nav.

## Approaches Considered

### Approach A: "Website-Only Forms" (Chosen)
Two forms on the Astro website, extending existing /api/sollicitatie. Email to Sandra. No marketing tool changes. Ships in 1 day.
- **Ruled in**: minimal scope, uses existing infrastructure, Sandra's workflow unchanged.

### Approach B: "Forms + Marketing Tool Visibility"
Same forms plus application counts in the marketing tool + Supabase storage. 2-3 days.
- **Ruled out**: adds scope without solving a stated pain. Can add later if Sandra wants counts.

### Approach C: "WhatsApp-First"
Replace form with WhatsApp wa.me link. Zero infrastructure.
- **Ruled out**: no structured data, doesn't scale. Worth adding as a secondary button later.

## Recommended Approach

**Approach A: Website-Only Forms.** Extend the existing Astro website with two forms and email delivery. No new infrastructure.

### Implementation Plan

#### API Changes (far-flare/src/pages/api/sollicitatie.ts)

**1. Extend the endpoint to handle sollicitatie submissions:**
- Use `multipart/form-data` (not JSON) since files are involved. Parse with `request.formData()`.
- Accept fields: `name` (required), `phone` (required), `email` (required), `beschikbaarheid` (required, enum: "Direct beschikbaar" / "Binnen 1-2 weken" / "Later"), `eigen_vervoer` (required, "ja"/"nee"), `message` (optional for sollicitatie type, required for contact type), `vacature_id` (optional), `vacature_titel` (optional), `type` ("vacature" or "open"), `cv` (optional File, max 5MB, pdf/jpg/png).
- Keep existing English field names (name, email, phone, message) for backward compatibility. New fields use Dutch names (beschikbaarheid, eigen_vervoer).
- Conditional validation: `message` required when type is undefined (contact form), optional for type="vacature"/"open".
- Client-side file validation: `accept=".pdf,.jpg,.jpeg,.png"` + size check before submit.
- Set `reply-to` header to the candidate's email so Sandra can hit Reply directly.
- Email subject: `Sollicitatie: {vacature_titel} - {naam}` or `Open sollicitatie: {naam}`.
- Structured email body (see template below).
- Keep existing rate limiting (5 per IP per minute). 429 shows: "Te veel pogingen. Probeer het over een minuut opnieuw."
- Keep existing honeypot field.

#### Email Template (far-flare/src/lib/email.ts)

**2. Structured sollicitatie email:**
```
Sollicitatie via website
========================
Vacature: {titel} ({plaats})
Type: Directe sollicitatie / Open sollicitatie

Kandidaat
---------
Naam: {naam}
Telefoon: {telefoon}
E-mail: {email}
Beschikbaarheid: {beschikbaarheid}
Eigen vervoer: Ja / Nee

Bericht
-------
{bericht of "Geen bericht meegegeven."}

CV: {bijgevoegd als bijlage / niet meegegeven}
```

#### Website Pages

**3. Per-vacature form (far-flare/src/pages/vacatures/[slug].astro):**
- Replace the mailto: "Solliciteer" button with an inline collapsible form.
- Button label: "Direct solliciteren". Clicking toggles form visibility via a client-side `<script>` (no framework island needed; form submission uses `fetch()` with FormData anyway).
- Hidden fields: vacature_id, vacature_titel (pre-filled from the page data).
- Visible fields (see field table below).
- Client-side validation: required fields get red border + inline Dutch error on blur. File input: `accept=".pdf,.jpg,.jpeg,.png"`, size check before submit (> 5MB shows "Bestand te groot, maximaal 5 MB.").
- Success state: green confirmation inline, form hidden, focus moves to confirmation. "Bedankt! We nemen binnen 2 werkdagen contact op."
- Error state: red message with "Probeer het opnieuw of bel ons direct." (429: "Te veel pogingen. Probeer het over een minuut opnieuw.")
- Mobile-first: must work on 375px Android Chrome. Proper `<label>` associations, focus management.

**4. Open sollicitatie page (far-flare/src/pages/solliciteren.astro):**
- New standalone page at /solliciteren.
- Intro text: "Geen passende vacature gevonden? Laat je gegevens achter en wij nemen contact op zodra er een match is."
- Same form fields as per-vacature, minus the vacature reference.
- type='open' in the submission.

**5. Navigation:**
- Add "Solliciteren" or "Open sollicitatie" link in the site footer.
- Add link on /vacatures listing page: "Geen passende vacature? Stuur een open sollicitatie."

**6. Vacature detail page cleanup:**
- Remove the existing mailto: link CTA.
- Keep phone number CTA if it exists (candidates can still call).

## Open Questions

1. **Email destination**: Should all sollicitaties go to `vacature@lightpersoneelsdiensten.nl` or should per-vacature emails go to the recruiter who created the vacature?
2. **Confirmation email to candidate**: Should the candidate receive a copy of their submission? Adds trust but requires a second SMTP call.
3. **WhatsApp as secondary CTA**: Add a "Liever WhatsApp?" link below the form that opens wa.me with pre-filled text?

## Success Criteria

1. A candidate on mobile can apply for a vacature on the website in under 60 seconds.
2. Sandra receives a structured email with all candidate info + optional CV attachment.
3. Sandra can hit Reply to respond directly to the candidate.
4. Open sollicitatie submissions are distinguishable from per-vacature ones in Sandra's inbox.
5. The form works on Android Chrome at 375px width.

The research was useful -- it confirmed that redirecting board candidates to your form would hurt volume -- but the solution was simpler than the investigation suggested. ## Eng Review Amendments (2026-09-04)

1. **Server-side file size check**: after parsing FormData, reject files > 5MB with 400 error. Prevents OOM from crafted requests.
2. **Backward compatibility**: branch on content-type in the endpoint. JSON requests (contact form) use existing logic with required message. FormData requests (sollicitatie forms) use new logic with optional message + file upload. Two code paths, zero regression risk.
3. **GDPR/AVG consent**: add "Door te solliciteren ga je akkoord met ons privacybeleid" with link to /privacy on both forms.
4. **Email destination**: always send to fixed SOLLICITATIE_TO env var, not per-vacature applyEmail. Simpler, no stale-address risk.
5. **Replace existing mailto links**: update both mailto links on /vacatures listing page (empty state + "geen passende vacature" CTA) to link to /solliciteren.
6. **vacature_id**: treat as opaque label in email body, no DB validation needed.
7. **Tests**: add endpoint tests for valid submission, file too large, invalid file type, missing required fields, message-optional for sollicitatie type, structured email template.
